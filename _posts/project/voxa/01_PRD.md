# PRD — 실시간 문서 인식 및 번역 안드로이드 앱

## 1. 개요

- 프로젝트명: (가칭) Voxa
- 한 줄 정의: 카메라·이미지·PDF로 입력된 문서를 온디바이스로 텍스트 인식(OCR) 및 번역하는 안드로이드 앱
- 핵심 목표
  - 실사용 가능한 문서 인식/번역 기능 제공
  - 온디바이스 AI 모델(ML Kit → 외부 오픈소스 모델) 적용 및 교체 실험을 위한 아키텍처 검증
  - 모듈 교체가 용이한 구조를 실제로 증명하는 레퍼런스 프로젝트

## 2. 배경 및 동기

- 모바일 AI 모델 적용 실습 및 온디바이스 최적화 경험 축적
- SDK 기반(ML Kit) 구현과 외부 오픈소스 모델(Gemma 3n 등) 구현을 비교하며 아키텍처 확장성 검증
- 향후 다른 AI 기능(요약, 문서 분류 등) 추가 가능성을 열어두는 구조 설계

## 3. 타겟 사용자 및 유스케이스

- 외국어 문서/메뉴/안내문을 즉석에서 촬영해 번역이 필요한 사용자
- 스캔된 PDF/이미지 파일을 일괄 번역하고자 하는 사용자
- (개발자 관점) 온디바이스 AI 모델 교체·비교 실험이 필요한 사용자(본인)

### 대표 시나리오
1. 카메라로 간판/메뉴판을 비추면 실시간으로 인식된 텍스트가 번역되어 오버레이된다.
2. 갤러리에서 이미지를 선택하면 OCR → 번역 결과가 화면에 표시된다.
3. PDF 파일을 선택하면 페이지별로 텍스트를 추출(또는 OCR)하고 번역 결과를 페이지 단위로 볼 수 있다.

## 4. 기능 범위 (Scope)

### 4.1 In Scope (MVP)
- 카메라 실시간 촬영 입력
- 갤러리 이미지 파일 입력
- PDF 파일 입력 (텍스트 기반 PDF, 스캔 PDF 모두 지원)
- OCR 결과 표시 (텍스트/필요 시 바운딩 박스)
- 번역 언어 선택 (source/target)
- 번역 결과 표시
- ML Kit 기반 OCR·번역 구현
- 외부 모델(Gemma 3n 등) 기반 OCR·번역 어댑터 최소 1종 구현 및 비교

### 4.2 Out of Scope (MVP 이후 고려)
- 음성 입력/출력(TTS)
- 다중 문서 배치 번역 자동화
- 클라우드 동기화/계정 시스템
- 문서 분류 등 기타 부가 AI 기능
- 실시간 협업/공유 기능
- PDF 원문 위치에 번역 텍스트를 정확히 오버레이하는 레이아웃 보존 번역 (최종 목표이나 MVP 이후 단계)

### 4.3 비목표 (하지 않을 것)
- 서버 기반 번역 API 사용 (온디바이스 원칙 유지)
- 특정 문서 양식(계약서, 영수증 등) 특화 파싱

## 5. 기능 요구사항 상세

| 기능 | 설명 | 우선순위 |
|---|---|---|
| 카메라 입력 | CameraX 기반 전체 화면 프리뷰, 문서 가장자리 자동 감지 후 수동 촬영 | High |
| 이미지 파일 입력 | 갤러리 선택, 단일/다중 선택 | High |
| PDF 파일 입력 | PdfBox 기반 텍스트 레이어 우선 추출, 텍스트 없을 시 내부적으로 OCR 자동 폴백 (사용자에게 선택 UI 노출 안 함) | High |
| PDF 페이지 번역 | 현재 페이지 단위 번역 (MVP), 전체 문서 일괄 번역은 Out of Scope | High |
| PDF 문서 요약 | 외부 LLM 어댑터(Gemma 등) 기반 전체 문서 요약 기능 | Medium (Phase 4 이후) |
| OCR 엔진 교체 | ML Kit / Gemma 3n 등 어댑터 교체 가능 | High |
| 번역 엔진 교체 | ML Kit Translate / Gemma 3n 등 어댑터 교체 가능 | High |
| 언어 선택 UI | source/target 언어 선택, 자동 감지 옵션 | Medium |
| 결과 저장/공유 | 번역 결과 텍스트 복사, 공유 | Medium |
| 다크모드 | 시스템 설정 연동 | Medium |
| 다국어 UI | 앱 UI 텍스트 다국어 리소스화 (번역 기능과 별개) | Medium |
| 모델 다운로드 관리 | 외부 모델 파일 다운로드/버전 관리 | Medium |
| 오프라인 동작 | 네트워크 없이 전 기능 동작 | High |

## 6. 비기능 요구사항 (NFR)

- **성능**: 이미지 1장 기준 OCR+번역 결과를 5초 이내(ML Kit 기준), Gemma 계열은 15초 이내 목표
- **안정성**: 모델 로딩 실패/OOM 상황에서 앱 크래시 없이 에러 상태 표시
- **프라이버시**: 입력 이미지/문서는 기기 내에서만 처리, 외부 전송 없음
- **확장성**: 신규 모델 어댑터 추가 시 도메인/UI 레이어 수정 없이 통합 가능
- **테스트 가능성**: 도메인 로직 unit test 커버리지 확보, 모델 정확도 평가셋 운영

## 7. 성공 기준 (Success Metrics)

- ML Kit 어댑터와 외부 모델 어댑터가 동일 인터페이스로 동작 (교체 시 UI/도메인 코드 변경 0건)
- 자체 평가셋(예: 이미지 30~50장) 기준 OCR 인식률/번역 품질 정성 비교 리포트 작성
- 크래시 프리 세션 비율 확보 (Firebase Crashlytics 기준)

## 8. 마일스톤 (상위 수준, Phase 문서와 연결)

| Phase | 내용 | 산출물 |
|---|---|---|
| Phase 0 | 기획/문서화 | PRD, 아키텍처 문서 등 |
| Phase 1 | 기본 구조 수립 | 스켈레톤 앱, 디자인 시스템, DI 구성 |
| Phase 2 | Mock 어댑터로 화면 흐름 완성 | 전체 UX 플로우 |
| Phase 3 | ML Kit 어댑터 구현 | 동작하는 MVP |
| Phase 4 | 외부 모델 어댑터 구현 | 모델 비교 가능한 버전 |
| Phase 5 | 테스트/모니터링 강화 | 테스트 커버리지, Crashlytics 연동 |
| Phase 6 | 배포 준비 | 릴리즈 빌드 |

## 9. 리스크 및 오픈 이슈

- 외부 LLM 모델의 앱 용량/다운로드 전략 미확정 (Play Asset Delivery vs 자체 다운로드)
- 모델 라이선스 조건 확인 필요 (상업적 배포 목적 여부에 따라)
- PDF 스캔 문서의 페이지 수/해상도에 따른 메모리 이슈 가능성
- 오래된 기기(저사양)에서 LLM 기반 어댑터 동작 가능 여부 미검증
