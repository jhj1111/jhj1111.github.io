# UI 화면 설계 명세 (Screen Design Specification)

이 문서는 `02_아키텍처_디자인시스템_코딩컨벤션.md`에 정의된 디자인 토큰을 기반으로, 실제 화면 레이아웃·상태·인터랙션을 구현 가능한 수준으로 명세한다. 토큰 값(컬러 hex, spacing dp 등)은 이 문서에서 중복 정의하지 않고 토큰 이름으로만 참조한다.

## 0. 디자인 컨셉 요약

- **컨셉명**: Soft Paper Minimal
- **방향**: 차가운 AI/테크 인상을 지우고, 따뜻한 종이 질감과 정갈한 스캐너 경험을 결합
- **핵심 톤**: Warm Cream 배경, Sage Teal(연한 청록) primary, Deep Terracotta accent, Pill 형태의 완만한 곡선
- **레퍼런스 인상**: Google Lens/CamScanner의 기능적 정갈함 + Day One/Things 3의 따뜻한 정서

## 1. 디자인 토큰 참조 (요약, 상세는 02번 문서 2.2~2.4 참조)

| 카테고리 | 토큰 | 용도 |
|---|---|---|
| 컬러 | `primary` (Sage Teal) | 주요 CTA, 선택 상태 |
| 컬러 | `secondary`/`accent` (Deep Terracotta) | 스캔 강조, 번역 결과 카드, 문서 감지 아웃라인 |
| 컬러 | `background` (Warm Cream) | 전체 배경 |
| 컬러 | `surface` (Warm Cream보다 한 톤 진한 베이지) | 카드/패널/바텀시트 |
| 컬러 | `textPrimary` / `textSecondary` | 본문 / 캡션·비활성 |
| Shape | `Radius.sm/md/lg/pill` | 12 / 16 / 20 / 28dp |
| Elevation | Ambient Shadow (약한 그림자) + Surface 색상 분리 병행 | 카드 경계 구분 (실외 시인성 고려) |

## 2. 공통 컴포넌트 명세

### 2.1 버튼

| 종류 | 형태 | 색상 | 사용처 |
|---|---|---|---|
| Primary Pill Button | `Radius.pill`, 높이 44~52dp | `primary` 배경 + `onPrimary` 텍스트 | 주요 액션 (번역 실행, 촬영) |
| Secondary Pill Button | `Radius.pill`, outline 스타일 | `surface` 배경 + `outline` 테두리 + `textPrimary` | 보조 액션 (복사, 취소) |
| Icon Button | 원형, 40~44dp | 배경 없음, 아이콘 `textSecondary` 또는 `textPrimary` | 상단바 아이콘 (뒤로가기, 설정) |
| FAB (촬영 버튼) | 원형 52dp, `primary` 배경 | 아이콘 `onPrimary` | 카메라 화면 중앙 하단 |

### 2.2 카드/패널

- 기본 카드: `Radius.md`(16dp), `surface` 배경, 얇은 `outline` 테두리(선택)
- 강조 카드(번역 결과): `Radius.md`, `accent` 계열 배경 톤(예: 연한 테라코타 tint)
- 바텀시트: `Radius.lg`(20dp, 상단 모서리만), 상단에 4dp 두께 32dp 너비의 drag handle 표시

### 2.3 언어 선택 칩(Toggle)

- `Radius.pill`, 선택 상태는 `primary` 배경 + 흰 텍스트, 비선택 상태는 `surface` 배경 + `outline` 테두리
- source ↔ target 사이에 화살표 아이콘(`textSecondary` 색)

### 2.4 아이콘 세트

- Tabler Icons 기준 통일 (`ti-camera`, `ti-photo`, `ti-file-text`, `ti-language`, `ti-arrow-left`, `ti-settings`, `ti-x`, `ti-bolt`, `ti-chevron-left/right`, `ti-dots`)
- 아이콘 크기: 상단바 16px, 본문 액션 20px, FAB 내부 22px

## 3. 화면별 설계

### 3.1 카메라 화면

**목적**: 실시간 촬영을 통한 문서 인식 입력

**레이아웃 (전체 화면 기준)**
- 카메라 프리뷰가 화면 전체를 차지 (고정 프레임 가이드 없음)
- 문서 가장자리 자동 감지 시, 감지된 윤곽선을 `accent` 컬러 2px 선으로 실시간 표시 (고정 사각형이 아닌 동적 외곽선)
- 상단: 반투명 그라데이션 스크림(`rgba(0,0,0,0.35)` → transparent) 위에 닫기 아이콘 / 안내 텍스트("문서 가장자리를 인식하고 있어요") / 플래시 아이콘
- 하단: 동일한 스크림 위에 갤러리 아이콘(좌) / 촬영 FAB(중앙) / PDF 파일 아이콘(우)

**상태**

| 상태 | 설명 | 시각 변화 |
|---|---|---|
| Idle | 문서 미감지 | 아웃라인 없음, 안내 텍스트 유지 |
| Detecting | 문서 가장자리 감지됨 | `accent` 아웃라인 표시, 안내 텍스트를 "탭하여 촬영"으로 전환 |
| Capturing | 촬영 진행 중 | FAB 축소 애니메이션, 짧은 플래시 효과(선택) |
| Processing | 인식/처리 중 | 하단 바텀시트에 로딩 인디케이터 (섹션 3.3 참조) |

**인터랙션**
- 탭하여 수동 촬영 가능 (자동 촬영은 향후 목표, MVP는 수동)
- 좌우 스와이프로 카메라 ↔ PDF 입력 전환은 지원하지 않음 (별도 진입점으로 분리, 섹션 3.2 참조)

### 3.2 PDF 화면

**목적**: PDF 파일의 텍스트 추출 및 번역 (카메라와 분리된 별도 흐름)

**레이아웃 — 몰입형 리더 (기본 상태)**
- 전체 화면에 PDF 페이지 콘텐츠만 표시 (렌더링된 페이지 이미지 또는 추출된 텍스트, 배경은 `background`)
- 상/하단 UI 바는 기본적으로 숨김

**레이아웃 — 노출 상태 (탭 시)**
- 상단바(반투명 `background`, 92% 불투명도): 뒤로가기 / 파일명 · 페이지 정보(`n/total`) / 더보기
- 하단바(동일 스타일): 이전 페이지 화살표 / **"이 페이지 번역" Primary Pill Button**(중앙) / 다음 페이지 화살표
- 두 바 모두 `outline` 색 1px 구분선으로 콘텐츠와 경계 표시

**전환 규칙**
- 화면 진입 시 1~2초간 상/하단 바를 자동 노출했다가 서서히 사라짐 (최초 힌트 제공 목적)
- 콘텐츠 영역 탭 → 바 노출/숨김 토글 (fade in/out, 200ms 내외)
- 페이지 이동은 좌우 스와이프 제스처로도 가능 (바 숨김 상태에서도 동작)

**내부 처리 (사용자에게 노출되지 않음)**
- 페이지 진입 시 PdfBox 기반 텍스트 레이어 추출을 우선 시도
- 텍스트 레이어가 없거나 비어 있으면 내부적으로 해당 페이지를 이미지 렌더링 후 OCR 파이프라인으로 자동 폴백
- 두 경로 모두 동일한 결과 도메인 모델로 반환되므로 화면 로직은 분기하지 않음 (필요 시 품질 안내 아이콘만 선택적으로 표시)

**번역 범위 (MVP)**
- 기본은 현재 페이지 번역만 지원
- 전체 문서 처리 시에는 "번역"이 아닌 **"요약"** 기능으로 제공 (향후 목표, Phase 4 이후)

### 3.3 결과 바텀시트 (카메라/PDF 공용 컴포넌트)

**목적**: 인식 및 번역 결과를 표시, 화면 컨텍스트(카메라/PDF)를 유지한 채로 확인

**상태**

| 상태 | 높이 | 내용 |
|---|---|---|
| Collapsed | 화면 하단 ~25% | drag handle, 언어 선택 칩, 번역 결과 요약(1~2줄) |
| Expanded | 화면 하단 ~70~90% | 원문 카드 + 번역 카드 전체, 복사/공유 버튼 |
| Loading | Collapsed 높이 유지 | 인디케이터만 표시 ("인식 중...", "번역 중...") |
| Error | Collapsed 높이 유지 | 에러 메시지 + 재시도 버튼 (도메인 에러 타입에 따라 문구 분기) |

**인터랙션**
- 위로 드래그 또는 탭 → Expanded 전환
- 아래로 드래그 또는 바깥 영역 탭 → Collapsed 전환
- Expanded 상태에서 언어 변경 시 번역만 재실행 (원문 재인식 없음)

**MVI 상태 매핑**
```kotlin
enum class SheetState { COLLAPSED, EXPANDED, LOADING, ERROR }

data class ResultScreenState(
    val sheetState: SheetState = SheetState.COLLAPSED,
    val recognizedText: RecognizedText? = null,
    val translatedText: String? = null,
    val sourceLang: LanguageCode = LanguageCode.AUTO_DETECT,
    val targetLang: LanguageCode = LanguageCode.ENGLISH,
    val error: DomainError? = null,
)
```

### 3.4 설정/기타 화면 (개요만)

- 언어 기본값 설정, OCR/번역 엔진 선택(개발/실험 목적, 향후 사용자 노출 여부 결정), 다크모드 강제 전환 옵션
- 상세 레이아웃은 Phase 4 이후 확정 (현재는 필수 화면이 아님)

## 4. 다크모드 화면 적용 규칙

- 모든 화면은 `background`/`surface`/`textPrimary`/`textSecondary`/`primary`/`accent`의 다크모드 값(02번 문서 참조)으로 자동 전환
- 카메라 프리뷰 자체는 다크모드 영향을 받지 않음 (카메라 피드는 항상 실사 그대로)
- 스크림/오버레이는 라이트·다크 공통으로 검정 반투명(`rgba(0,0,0,0.35~0.45)`) 유지 (배경 톤과 무관하게 카메라 피드 위 가독성 확보 목적)

## 5. 접근성 체크리스트

- [ ] `textSecondary`가 본문에 쓰이는 경우 대비 4.5:1 이상 확보 (캡션 등 작은 텍스트는 별도 확인)
- [ ] 몰입형 화면의 탭-토글 UI가 TalkBack 포커스 순서에서 자연스럽게 동작하는지 확인
- [ ] 바텀시트 확장/축소가 스크린 리더로도 상태 변화가 안내되는지 확인 (`liveRegion` 등)
- [ ] 시스템 폰트 크기 확대 시 Pill 버튼 텍스트가 잘리지 않는지 확인

## 6. 향후 확장 (참고용, 현재 스코프 아님)

- PDF 원문 위치에 번역 텍스트를 정확히 오버레이하는 레이아웃 보존 번역 (좌표 기반)
- 전체 문서 요약 결과를 위한 별도 요약 결과 화면/카드
- 설정 화면에서 OCR/번역/요약 엔진을 사용자가 직접 전환하는 UI
